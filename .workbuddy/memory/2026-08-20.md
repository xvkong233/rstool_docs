## git push 在本沙箱环境卡死（GCM GUI 交互）
- 本机 remote 用 HTTPS，凭证走 Windows Git Credential Manager (GCM)。`git push` / `git credential fill` 在无头后台 Bash 里会**永久卡死**（无输出、无报错、持续数分钟），进程出现 `git-credential-helper-sel` / `git-remote-https`。而只读的 `git ls-remote` / `git fetch` 能成功（GCM 缓存 token 对只读有效），但 push（写）触发交互授权弹窗，后台无 GUI 弹不出 → 阻塞。
- 已试：`credential.interactive=never`、`GCM_INTERACTIVE=never GCM_MODALPROMPT=0`、URL 内嵌 token 的 `credential fill` 全部同样卡在 fill 阶段（连 `echo` 都不输出）。
- 结论：**本沙箱无法自动 `git push` 到 GitHub**。commit 照常做（需 `dangerouslyDisableSandbox:true` 落盘），push 请用户在 **GitHub Desktop**（已有登录态）点 Push，或用户提供 **GitHub PAT** 后用 `git -c credential.helper= push https://<user>:<PAT>@github.com/...` 推。
- 顺带发现：这 8 个命令（楼梯×4 + rsWalker/rsZigZagRamp/rsFadingStair/rsFadingStairVertical）的 illustrations、对应 png、md 之前就已推到 origin/main，只是图注是占位"功能"；本次只是把占位图注补成真实描述（commands.json 一文件 8 增 8 删）。
